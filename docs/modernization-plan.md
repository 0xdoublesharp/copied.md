# copied.md modernization plan

## Outcome

Copy a Markdown selection or document, choose a destination or format, and paste it without losing content. Start with browser and VS Code users, and make the same operation available from the macOS keyboard, T3 Code, scripts, and agents. All conversion runs locally. The user initiates every clipboard read and write.

The starting point is the in-progress browser extension move and VS Code extension in this checkout. The existing lockfile built Chrome, Edge, Firefox, and VS Code, and 189 tests and lint passed. Prettier flagged seven source and lockfile paths. Formatter probes exposed issues those tests missed, and a separate compiler probe showed why a green root Vue check alone is insufficient.

Start with a small preflight change. Reconcile both extension trees file by file, including their divergent Twitter context-menu tests, and preserve any unique work before removing confirmed duplicates. Exclude generated packages, build output, and the pnpm-generated lockfile from formatting checks while keeping the lockfile tracked. Pin the existing package manager consistently, make CI's frozen install explicit, add the Edge build, and establish explicit type-check commands before upgrading packages. Keep the baseline, compiler migration, browser stack, and package manager changes independently reviewable.

## 2. Preserve Markdown meaning in the shared converter

Keep `packages/converters` as the only conversion engine. Use one CommonMark/GFM parse with typed nodes and a shared definition index. Resolve reference links, reference images, and footnotes before rendering. Share traversal, semantic plain text, link validation, and HTML sanitization. Keep each destination's escaping, supported constructs, and length policy in its renderer. Keep compatible Markdown source intact where the destination can consume it. Use `remark-stringify` with GFM support as the starting point for transformed Markdown and verify the result against each destination's dialect. For raw HTML fallbacks, use parsed content so spacing is preserved and non-content elements are discarded predictably. When a caller supplies a valid source URL, resolve relative links against it and apply the same protocol policy. Otherwise preserve their text and report any link that will lose its destination on paste. [remark-stringify](https://github.com/remarkjs/remark/tree/main/packages/remark-stringify)

Define one operation that accepts Markdown and a named target. Return `schemaVersion`, `target`, `representations`, optional `exports`, metrics with explicit counting units, and diagnostics with stable codes and severity. Diagnostics cover unsupported constructs, dropped formatting, and limit overruns. Produce the complete conversion by default and warn about length. Offer split or trim only as explicit actions that retain complete code spans, links, and graphemes. Keep parsing independent of DOM, clipboard, and filesystem APIs. Preserve existing platform IDs and VS Code command IDs at the adapters. Map a saved browser `html` preference to `rich-text`, keep the old VS Code HTML command as an alias for `html-source`, and map existing `slack` paste commands and settings to `slack-paste`. Expose `slack-api` as a separate opt-in output.

Plain Text retains list indentation, link labels and URLs, and readable table fallbacks. Fix doubly prefixed footnote anchors and test each link and backlink. Apply the same URL protocol policy to every HTML flavor, including the custom Slack, Facebook, and Telegram renderers. Keep remote images out of the live preview and use alt text or links in the default clipboard profile.                   |

**Acceptance.** Use shared regression fixtures for references, footnotes, non-default list starts, nested and multiline blocks, literal punctuation, code delimiters, escaped table pipes, Unicode, and line endings. Assert exact clipboard representations and structural properties such as resolved anchors and preserved cell count. The previously reproduced loss cases should fail before each fix and pass after it. Verify that conversion never mutates its input and that clipboard adapters report what they actually wrote.

## 3. Ship the browser, VS Code, CLI, and MCP workflows

- **Browser.** Give the popup and selection menu the same format list, using shared target metadata. Add a keyboard command for the last selected format and keep a visible destination picker. Prefer source selection from editable controls and Markdown code blocks when the DOM provides it. Use the browser selection as received when source structure is unavailable, with the popup as an explicit paste-and-preview path. Consolidate clipboard writes across popup, content script, and offscreen document. The current Chrome manifest grants `offscreen` and the Edge manifest omits it despite Edge API support. Share one in-flight offscreen creation. Serialize explicit copy commands so the latest successful request owns the clipboard. Send messages to the intended writer and return the MIME types actually written so rich requests can try the appropriate writer before falling back. Use a visible extension-controlled route or a clear failure on browsers without that fallback. Test focused pages, frames, restricted pages, concurrent writes, and permission or focus failures. Verify service-worker startup with entity-heavy Markdown before retiring the current DOM shim. Keep history off by default, store only settings and recent target IDs, and remove content snippets from logs. [Chrome offscreen lifecycle](https://developer.chrome.com/docs/extensions/reference/api/offscreen), [Edge API support](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/api-support)
- Test access to editable selections and frames through user-invoked `activeTab` and scripting before retaining the current persistent `<all_urls>` content script. Capture editable text and the selected range from the invoking frame when accessible. Compare it with `info.selectionText` in the supported browsers to document where structure is lost, and use the browser-provided text as a best-effort fallback. Keep a permission matrix and a visible fallback for unavailable pages and frames. [Chrome activeTab permission](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [Chrome context menu event data](https://developer.chrome.com/docs/extensions/reference/api/contextMenus#type-OnClickData)
- **VS Code.** Add one **Copy Markdown As…** picker. Copy non-empty selections in document order with paragraph breaks between them. With an empty selection, offer the entire document for Markdown files and make the action clear in the picker. Preserve existing named commands and keybindings. Use VS Code's text clipboard API for text and source outputs. It writes locally even from remote workspace hosts. Expose rich clipboard copy when a UI-side local writer is available and show the system shortcut otherwise. Activate the packaged VSIX on the minimum advertised VS Code version and a current release. [VS Code Clipboard API](https://code.visualstudio.com/api/references/vscode-api#Clipboard), [VS Code remote extension clipboard behavior](https://code.visualstudio.com/api/advanced-topics/remote-extensions#_using-the-clipboard)
- **CLI and MCP.** Package a documented CLI that reads stdin or a file, lists available targets, and can emit a single representation or structured JSON with a stable error and diagnostics schema. The initial command shape can be `copied-md convert --to rich-text --json` and `copied-md targets --json`. Keep default stdout suitable for pipelines. Clipboard access requires an explicit CLI action and the local desktop context. Provide a stdio MCP server with the same target catalog and pure conversion, taking Markdown supplied in the call. Keep desktop clipboard, filesystem, and posting outside the MCP tool contract. Exercise initialization, tool discovery, conversion, invalid inputs, and Unicode in a protocol smoke test. Reserve server stdout for MCP messages. Verify identical outputs and diagnostics across the CLI, MCP, and existing app adapters with shared fixtures. [MCP stdio transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#stdio)

**Acceptance.** A selection converts through the browser menu and the VS Code picker. Clipboard denial gives an actionable error while preserving an existing clipboard when conversion or capability checks fail. Plain fallback is visible, and rich mode never presents a plain write as a rich success. CLI and MCP outputs agree, including warnings and errors, from an installed package on a clean machine.

## 4. Make the macOS and T3 Code workflow the default handoff

Start with a **Copy as…** Shortcuts Quick Action that reads the Markdown already copied to the clipboard. Also accept selected text from Services where the app supplies it. Use a small AppKit helper to capture the incoming text and pasteboard `changeCount` before showing the picker. Show recent targets, convert locally through the CLI, and write one item with HTML and readable plain text. Prepare all representations first and check `changeCount` immediately before writing to catch a newer copy made while the picker was open. Treat this as a stale-copy guard and test cancellation and overlapping invocations. [Apple Quick Actions](https://support.apple.com/en-bh/guide/shortcuts-mac/apd163eb9f95/mac), [AppKit pasteboard](https://developer.apple.com/documentation/appkit/nspasteboard)

Use the paste pilot to decide if a supported native app needs RTF. If it does, compare deterministic RTF generation with AppKit import of sanitized HTML. Prove startup, fidelity, latency, and no remote resource loads before adding the RTF representation. For the local pilot, build the helper locally. For a downloadable binary, verify the macOS signing and notarization path from a clean machine before release.

For T3 Code, the first end-to-end flow is **Copy Message → macOS shortcut → paste into the destination**. It uses the assistant message Markdown T3 Code already passes to the copy button. Verify that results copied from a thread attached to a remote environment still go through the local clipboard. Agents that already have Markdown can call the MCP conversion tool. A future upstream **Copy as…** control can reuse `TimelineAssistantRows.tsx`, `MessageCopyButton.tsx`, and the multi-format clipboard hook after the copied.md contract is stable. The hook would need to report the format actually written to support accurate feedback. Keep the original copy action as Markdown for downstream reuse. [T3 Code assistant message copy](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/chat/TimelineAssistantRows.tsx), [T3 Code clipboard hook](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/hooks/useCopyToClipboard.ts)

**Trade-off.** The Shortcut and small helper cover multiple apps with one install and modest maintenance. A menu-bar app would give more control over global hotkeys and discovery, with signing, lifecycle, and permission work. A T3 Code patch would remove a click for that app, with upstream and version coordination. Start with the Shortcut, then use real paste results to decide whether either additional surface is warranted.

**Acceptance.** Run a small paste pilot as soon as a packaged CLI and pasteboard writer are ready. Install on a clean supported Mac, verify that the imported Shortcut can find its executable and run, and copy a T3 Code message containing a table, links, and a code block. Convert with the shortcut and paste into an ordinary desktop destination. Test the real payload in Slack web and desktop, Telegram web and desktop, and at least one native rich-text app and one document editor. Include a terminal or text editor to verify that plain paste stays readable. Record which representations each supported destination retains. Downgrade the advertised capability where client behavior differs.

## 5. Package, document, and expand

- Produce browser bundles, an installable VSIX, and a CLI package containing the MCP entrypoint. Bundle the shared converter to JavaScript or depend on a compiled release. The current workspace export points at raw `.ts`. Inspect package contents and test activation or invocation from installed artifacts outside the repo. Include the confirmed license and an installation README. Decide the Firefox manifest version and retain the published Gecko ID if one exists. Verify the signing route on release-channel Firefox and declare the actual data collection behavior. Document local installation, the macOS Shortcut and helper, supported formats, and observed paste limitations. CI should build and package without publishing. Keep publishing as a separate release step. [Node TypeScript support](https://nodejs.org/api/typescript.html#type-stripping-in-dependencies), [Firefox signing and distribution](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/), [Firefox data declarations](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/)
- Add Markdown-table-to-TSV first after the release. Provide CSV as file export where useful. Verify embedded delimiters, tabs and newlines, and that cells intended as text remain text when pasted into supported spreadsheet clients. Consider HTML-to-Markdown import, a menu-bar installer, and additional app presets once there is a demonstrated workflow for them.
- **Release criteria.** The prior content-loss fixtures pass. The clean toolchain checks prove TypeScript 7 and Vue template checks execute. Installable packages smoke-test successfully. The macOS copy journey and destination paste matrix pass for every format advertised as supported. User-facing settings and copy feedback explain actual behavior, including fallback.
